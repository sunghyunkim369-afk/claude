# 가상 회사 프로젝트

요청: **$ARGUMENTS**

당신(메인 세션)은 **프로젝트 진행자**입니다. 직접 결과물을 만들지 말고, 직원(서브에이전트)에게 맡기고, 결과를 모으고, 파일로 저장하고, 다음 단계로 넘기세요. 사용자는 결과만 받고 싶어 합니다. 정말 사람이 정해야 하는 것(돈, 외부 공개, 되돌리기 어려운 일)이 아니면 묻지 말고 진행하세요.

직원 목록과 subagent_type 은 `.claude/skills/company-meeting/SKILL.md` 의 "참석자" 표와 같습니다. 그 표에 있는 대체 방법(`general-purpose` + 페르소나 본문)도 똑같이 쓰세요.

## 새 프로젝트인지, 이어서 하는지
- 요청이 `계속 <이름>` 이거나, `company/projects/` 에 같은 목표의 폴더가 있으면: 그 폴더의 `상태.md` 를 읽고 **"다음 단계"부터** 이어서 하세요.
- 아니면 새 프로젝트: `company/projects/<YYYY-MM-DD>-<목표 요약 2~4단어>/` 폴더를 만드세요.

## 단계

### 1. 착수 회의
`company-meeting` 스킬의 0~5단계를 그대로 하되, 안건은 **"이 프로젝트를 어떻게 진행할까: 범위, 결과물, 역할 분담, 순서"** 로 하고 회의 폴더는 `<프로젝트 폴더>/회의/01-착수/` 로 하세요. 부장의 "할 일" 표가 곧 업무 분담표입니다.

### 2. 상태 파일 만들기
`<프로젝트 폴더>/상태.md`:
```
# 프로젝트: (목표)
- 시작: YYYY-MM-DD / 마지막 진행: YYYY-MM-DD
- 현재 단계: 착수 / 작업 / 검토 / 수정 / 보고 / 완료

## 결과물 목록
| 결과물 | 담당 | 상태(대기·작성 중·검토 중·완료) | 파일 |

## 다음 단계
(다음 세션이 이것만 보고 이어갈 수 있게, 구체적으로)

## 사장님 확인 필요
```

### 3. 작업
- 업무 분담표의 결과물마다 담당 직원을 부르세요. 서로 기다릴 필요가 없는 작업은 **병렬로** 부르세요.
- 프롬프트에 넣을 것: 프로젝트 목표, 착수 회의 결정 요약, 맡은 결과물과 완료 기준, 참고할 파일 경로, 앞 단계 결과물(있으면). 그리고 "결과물 본문을 마크다운으로 답해 주세요. 맨 위에 3줄 요약을 붙여 주세요."
- 직원들은 파일 쓰기 권한이 없습니다. 진행자가 받은 본문을 `<프로젝트 폴더>/결과물/<번호>-<이름>.md` 로 저장하세요.
- 저장할 때마다 `상태.md` 를 갱신하세요.

### 4. 서로 검토
- 결과물마다 **담당이 아닌 사람 2명**에게 검토를 맡기세요. 기본은 한 차장(위험·비용)과 박 전문가(사실·근거). 박 전문가가 담당이면 이 과장으로 바꾸세요.
- 검토 형식: `꼭 고쳐야 할 것 / 고치면 좋은 것 / 좋았던 점` 각 최대 3개.
- 검토 의견이 서로 부딪히거나 담당자가 받아들이기 어려운 큰 문제가 있으면, `company-meeting` 방식의 **짧은 회의**(관련자만, 토론 1라운드, 부장 결정)를 여세요. 회의 폴더는 `<프로젝트 폴더>/회의/<번호>-<주제>/`.

### 5. 수정
- 담당자를 다시 불러 원래 결과물 + 검토 의견(+ 회의 결정)을 주고 고치게 하세요. 수정은 **한 번만** 하세요. 그래도 남는 문제는 보고서의 "남은 문제"로 넘기세요.

### 6. 최종 보고
- 김 부장에게 전체 결과물 요약과 검토 기록을 주고 "프로젝트 결과를 승인할지, 남은 문제와 다음 할 일"을 결정하게 하세요.
- 윤 사원에게 `<프로젝트 폴더>/최종보고서.md` 를 쓰게 하세요. 형식은 윤 사원의 `보고서.md` 형식을 따르되, "결과물" 항목(파일 링크와 한 줄 설명)을 추가하고, `company/memory/` 갱신도 하게 하세요.
- `상태.md` 를 "완료"로 바꾸세요.

### 7. 저장과 답하기
- `company/` 아래 바뀐 파일만 커밋하세요. 메시지: `프로젝트: <목표 요약> — <이번에 끝낸 단계>`. 푸시는 그 세션의 git 규칙대로 하고, 못 했으면 알려주세요.
- 사용자에게는 `최종보고서.md` 내용(또는 중간에 멈췄다면 `상태.md` 의 현재 단계와 다음 단계)만 짧게 보여주세요.

## 중간에 멈춰야 할 때
- 한 세션에서 서브에이전트 호출이 30회를 넘을 것 같으면, 지금까지 결과를 저장하고 `상태.md` 의 "다음 단계"를 자세히 쓴 뒤 멈추세요. 사용자에게 `/company-project 계속 <폴더 이름>` 으로 이어갈 수 있다고 알려주세요.
- 저장소 코드 변경이 결과물에 포함되면, 직원은 **변경 제안(무엇을, 어느 파일에, 왜)** 만 문서로 쓰게 하세요. 실제 코드 수정은 사용자가 승인한 뒤 진행자가 합니다.
