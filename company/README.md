# 가상 회사

Claude Code 세션 안에서 돌아가는 가상 회사예요. 직원들이 회의하고, 의견이 갈리면 토론하고, 부장이 결정하고, 서기가 회의록과 보고서를 남겨요. 사용자는 보고서만 받아보면 돼요. API 키는 따로 필요 없어요. 세션이 쓰는 Claude가 직원 역할을 맡아요.

## 쓰는 법

이 저장소를 연 Claude Code 세션에서:

| 명령 | 하는 일 |
|---|---|
| `/company-meeting <안건>` | 회의 한 번: 의견 → 토론(최대 3라운드) → 부장 결정 → 회의록·보고서 |
| `/company-project <목표>` | 프로젝트: 착수 회의 → 업무 분담 → 작업 → 서로 검토 → 수정 → 최종 보고 |
| `/company-project 계속 <폴더 이름>` | 멈춘 프로젝트를 다음 세션에서 이어서 하기 |

예:
```
/company-meeting HS코드 찾기에 사진으로 품목 인식 기능을 넣을까?
/company-project 직구 반입 체커 사용 설명서와 FAQ 만들기
```

## 직원

| 이름 | 파일 | 관점 | 회의에서 하는 일 |
|---|---|---|---|
| 김 부장 | `.claude/agents/bujang-kim.md` | 성과·일정·우선순위 | 토론을 듣고 최종 결정, 할 일 배정 |
| 박 전문가 | `.claude/agents/expert-park.md` | 사실·규정·근거 (무역·관세·데이터) | 전문 의견, 사실 확인 |
| 이 과장 | `.claude/agents/gwajang-lee.md` | 일정·인력·실행 가능성 | 실행 계획, 범위 조정 |
| 장 대리 | `.claude/agents/daeri-jang.md` | 사용자 경험·현장 | 사용 장면, 빠른 시도 아이디어 |
| 한 차장 | `.claude/agents/chajang-han.md` | 비용·위험 (레드팀) | 일부러 반대 의견, 찬성 조건 제시 |
| 윤 사원 | `.claude/agents/secretary-yoon.md` | 기록 | 회의록·보고서·회사 기억 갱신 |

토론이 실제로 일어나게 하려고 이렇게 만들었어요:
- 직급보다 **서로 부딪히는 관심사**를 줬어요 (근거 vs 일정 vs 사용자 vs 위험).
- 1라운드는 **동시에** 의견을 내서 남의 의견에 휩쓸리지 않게 해요.
- "새 근거를 듣기 전에는 입장을 바꾸지 말라"는 규칙이 있어요.
- 모두 찬성하면 한 차장에게 반대 논리를 한 번 더 요청해요.
- 끝내는 조건이 정해져 있어요: 쟁점 해소, 같은 말 반복, 3라운드 중 하나면 끝나고, 부장이 결정해요.

## 결과가 쌓이는 곳

```
company/
├── memory/
│   ├── decisions.md     # 지금까지의 결정 (다음 회의 때 참고)
│   └── projects.md      # 진행 중 / 완료된 할 일
├── meetings/<날짜-안건>/
│   ├── 회의록.md         # 발언 요약, 쟁점, 결정, 소수 의견, 발언 원문
│   └── 보고서.md         # 1분 요약
└── projects/<날짜-목표>/
    ├── 상태.md           # 어디까지 했는지, 다음 단계 (이어서 할 때 이걸 읽어요)
    ├── 회의/…
    ├── 결과물/…
    └── 최종보고서.md
```

회의가 끝나면 `company/` 아래 바뀐 파일을 커밋해요. 클라우드 세션은 컨테이너가 사라지면 커밋·푸시하지 않은 기록도 사라지니, 회사 기억을 이어가려면 푸시까지 해야 해요.

## 바꾸기

- **직원 성격·관점 바꾸기:** `.claude/agents/<이름>.md` 의 본문을 고치세요. 예를 들어 박 전문가의 전문 분야를 마케팅으로 바꿀 수 있어요.
- **직원 추가:** 같은 형식으로 파일을 하나 더 만들고(`name` 은 영문 소문자와 `-`만), `.claude/skills/company-meeting/SKILL.md` 의 참석자 표에 한 줄 추가하세요.
- **사용량 줄이기:** 직원 파일의 `model: inherit` 를 `model: sonnet` 이나 `model: haiku` 로 바꾸면 덜 들어요. 부장과 박 전문가는 그대로 두고 나머지만 바꾸는 것도 방법이에요.
- **토론 라운드 수:** `company-meeting/SKILL.md` 의 "3. 토론 라운드 (최대 2번)" 을 고치세요.

## 알아둘 점

- 직원 파일(`.claude/agents/`)은 **세션이 시작될 때** 읽혀요. 파일을 추가·수정한 세션에서는 바로 안 보일 수 있어요. 그래도 회의는 돼요. 스킬이 직원 파일 내용을 읽어 일반 에이전트에게 역할을 맡겨요.
- 다른 저장소에서도 쓰려면 `.claude/agents/`, `.claude/skills/company-*`, `company/` 폴더를 그대로 복사하세요.
- 직원들은 회의 중 저장소 코드를 고치지 않아요. 코드 변경은 "할 일"이나 "변경 제안"으로 남고, 사용자가 시키면 그때 고쳐요.
- 같은 모델이 모든 역할을 맡아서 생기는 한계가 있어요. 중요한 결정은 보고서의 "반대 의견"과 "사장님 확인 필요"를 꼭 읽어 보세요.
