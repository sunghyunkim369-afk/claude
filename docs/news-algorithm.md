수집 경로는 두 가지입니다.

1. **언론사 RSS 전체**를 받아, 12개 무역 주제 단어가 하나라도 들어간 기사만 남깁니다. ("수입"만 있으면 소득 기사일 수 있어서 제외)
2. **Google 뉴스 검색 RSS**로 주제별 검색(관세, 수출통제, 반덤핑·무역구제, FTA·통상협정, 경제제재, 해운·물류, 공급망·핵심광물, 환율, 유가·원자재, 보조금·산업정책, 통관·원산지, 수출입 동향) + 정책브리핑(`site:korea.kr`) + 영문 통신사 기사를 받습니다. 결과 중 **위 표에 있는 언론사(이름 또는 원문 도메인)** 기사만 남깁니다. Daum 같은 포털 재전송은 원 언론사를 알 수 없어서 버립니다.

2026-10 점검에서 정책브리핑 부처별 RSS(404), USTR(404), 미 상무부(403), KOTRA(빈 피드)는 동작하지 않아 뺐습니다. 점검은 `.github/workflows/feed-probe.yml` 을 수동 실행하면 다시 할 수 있습니다.

## 2. 분류

기사마다 단어 규칙으로 정합니다. (GitHub Secret `AI_API_KEY` 가 있으면 Eyefeet AI 가 한 번 더 분류·요약합니다.)

- **주제**: 12개 주제 단어 점수(제목 2점, 본문 1점) 최고값. "관세"는 반덤핑 관세·관세청 안에도 들어 있어 동점이면 더 구체적인 주제를 고릅니다. Google 뉴스 검색으로 들어온 기사는 검색 주제를 우선하되, 제목·요약에 주제 단어가 하나도 없으면 수출·수입·무역 단어가 있을 때만 "수출입 동향"으로 남기고 나머지는 버립니다(검색이 본문·유사어로도 결과를 줘서 엉뚱한 기사가 섞이기 때문).
- **상대국**: 미국·중국·EU·일본·베트남·멕시코·캐나다·러시아·중동. 영문 단어는 단어 앞부분이 맞아야 인정합니다(“EU”가 “Reuters” 안에서 잡히지 않게).
- **섹터**(최대 2개): 반도체, 자동차, 2차전지, 철강·금속, 석유화학·에너지, 조선·해운물류, 기계·전자, 소비재·농식품
- **조치 방향**: 강화(up) · 완화(down) · 중립(neutral) · 동향(info)
  - 단어 점수: 부과·인상·통제·금지·압박·위협 등 강화 단어 1점, 인하·유예·면제·해제·폐지·타결 등 완화 단어 1점
  - **짝 점수 2점**: "조치 대상(관세·제재·규제·통제·반덤핑…) + 방향 동사"가 12자 안에 붙어 있으면 2점. 예) 제재 면제·관세 인하·관세 상한 → 완화, 추가 관세·관세 압박·관세 부과 → 강화
  - 단어만 세던 첫 버전은 "제재 면제"가 제재(강화) 1 : 면제(완화) 1 로 비겨 중립이 됐고, 실제로 기사 1,162건 중 963건(83%)이 중립이었습니다. 짝 점수를 넣은 뒤 강화 193 · 완화 82로 늘었습니다.
  - 환율·운임·수출 실적·원자재·공급망처럼 정책 조치가 아닌 주제는 방향이 없으면 "중립" 대신 **"동향"** 으로 표시합니다(393건). "중립"은 이제 정책 기사인데 조치 방향이 드러나지 않는 분석·전망 기사(약 1/3)만 뜻합니다.
- 게시판·인사·부고·사진 단신과 지명 속 우연한 단어(해운대 → "해운")는 제외합니다.
- **한국 관련도**: 정부 발표이거나 한국·국내·수출기업 등이 언급되면 1, 국내 기사 0.8, 해외 기사 0.5

**중복 묶기**: 제목을 2글자 조각(shingle)으로 나눠 Jaccard 유사도가 0.55 이상이고 3일 이내면 같은 사건으로 보고, 새 기사로 세지 않고 "보도한 언론사"만 추가합니다 (Broder, 1997).

## 3. 이슈 점수 — 팀의 0.6/0.4 공식을 고친 부분

**이슈 = 주제 × 상대국** (예: 미국 관세, 중국 수출통제, EU 반덤핑·무역구제). 매주 같은 기준으로 묶이므로 지난주·지난달과 비교할 수 있습니다.

### 기존 공식의 문제

원래 공식은 *점수 = 0.6 × 보도량 + 0.4 × 증가율* 이었는데, 실제 데이터에 넣으면 다음 문제가 생깁니다.

1. **단위가 다름**: 보도량(건수, 0~수백)과 증가율(%, -100~수천)을 그대로 더하면 어느 한쪽이 점수를 독차지해서 0.6/0.4 비율이 의미가 없습니다.
2. **작은 수 폭주**: 직전 주 1건 → 이번 주 3건이면 +200%라 하루짜리 소식이 상위로 올라옵니다. 직전 주 0건이면 계산 자체가 안 됩니다.
3. **수집량 변화에 휩쓸림**: 출처를 늘리거나 큰 사건으로 뉴스 전체가 많아진 주에는 모든 이슈의 증가율이 같이 오릅니다.
4. **출처 품질·중복 무시**: 같은 기사 재전송 10건과 서로 다른 언론사 10곳의 보도가 같은 점수입니다.

### 고친 공식

```
점수 = 100 × (0.6 × V + 0.4 × M) × (0.6 + 0.4 × R)
```

- **V (보도량, 0~1)**: 기사별 무게 `w = 신뢰도 × (0.6 + 0.4 × 한국관련도) × 0.5^(경과일/3.5) × min(2, 1 + 0.25 × (보도 언론사 수 − 1))` 를 더한 뒤 `log(1+V) / log(1+V_max)` 로 정규화. 로그를 쓰는 이유는 보도량이 몇 개 큰 이슈에 몰리는 분포(멱법칙)라서, 2위 이하도 구분되게 하기 위해서입니다. 최신성 반감기 3.5일은 주간 창(7일)의 절반입니다.
- **M (추세, 0~1)**: 건수 대신 **비중**을 비교합니다. Baker·Bloom·Davis(2016)의 경제정책 불확실성(EPU) 지수와 Caldara 외(2020)의 무역정책 불확실성(TPU) 지수는 "전체 기사 중 해당 주제 기사 비율"로 지수를 만들어 수집량 변화를 없앱니다. 같은 방식으로
  `share = (이슈 기사 수 + 0.5) / (전체 무역 기사 수 + 0.5 × 이슈 종류 수)` 를 이번 주와 직전 4주에 대해 구하고,
  `M = 0.5 + 0.5 × tanh(ln(share_이번주 / share_직전4주))` 로 둡니다. 평소와 같으면 0.5, 비중이 e배(약 2.7배) 늘면 0.88, 줄면 0.5 아래로 갑니다. +0.5 평활 덕분에 0건→1건이 무한대로 튀지 않고, tanh 로 범위가 0~1에 묶여 V와 같은 단위가 됩니다. 과거 데이터가 없으면 M = 0.5(중립).
- **R (한국 관련도 평균)**: 해외 이슈라도 0.6배까지만 깎아서 완전히 빠지지는 않게 했습니다.
- **후보 조건**: 이번 주 기사 2건 이상(정부 발표는 1건도 허용).

### Top10 고르기

점수 순으로만 자르면 "미국 관세"와 "미국 상호관세 협상"처럼 비슷한 이슈가 위를 채웁니다. **MMR**(Carbonell & Goldstein, 1998)로
`0.7 × 점수 − 0.3 × (이미 고른 이슈와의 최대 유사도)` 가 가장 큰 것을 하나씩 고르고(유사도 = 같은 주제 0.5 + 같은 나라 0.3 + 섹터 겹침 0.2), 한 섹터가 주 섹터인 이슈는 최대 3개로 제한합니다. 고른 10개는 화면에서 점수 순으로 보여 줍니다.

## 4. 섹터 노출도 (50 = 평소 수준)

```
노출도 = 50 + 100 × (M_섹터 − 0.5) × n / (n + 8)      (n = 이번 주 섹터 기사 수)
```

M_섹터는 위 추세 공식을 섹터 기사 비중에 적용한 값입니다. 50보다 높으면 평소(직전 4주)보다 무역 뉴스에 많이 노출됐다는 뜻입니다. 기사 수가 적을수록 50 쪽으로 당기는 축소(shrinkage) 계수 n/(n+8)을 곱해, 기사 4건짜리 섹터가 100 가까이 튀지 않게 했습니다. (첫 실데이터 계산에서 기계·전자가 4건으로 98.9가 나와 넣은 보정입니다.) **상태**는 방향이 있는 기사끼리만 비교합니다: `(강화 − 완화) / (강화 + 완화)` 가 1/3 이상이면 강화, −1/3 이하면 완화, 그 사이거나 방향 기사가 2건 미만이면 보합. (처음에는 분모가 전체 기사 수라서 동향 기사가 많은 섹터는 늘 보합이 됐습니다.)

## 5. 그 밖의 화면

- **공급망 리스크 신호**: 리스크 주제(수출통제·제재·해운·공급망·유가/원자재) 이슈 상위 5개. 점수 70 이상 심각, 55 이상 주의, 그 아래 관찰.
- **주요 뉴스**: 이번 주 기사를 무게(w) 순으로 20건, 같은 이슈는 3건까지. 제목을 누르면 원문으로 이동합니다.
- **이번 주 요약(Bearing)**: AI 키가 있으면 Top 이슈만 근거로 AI가 쓰고, 없으면 상위 3개 이슈의 보도량·증감·영향 섹터로 만듭니다.
- **국가·품목별 무역 흐름**: 실제 통계 출처(관세청 수출입무역통계 API 키)가 아직 없어 숨겼습니다. `trade: null` 자리에 붙이면 다시 나타납니다.

## 6. 매주 갱신 과정

1. **6시간마다** (`news-collect.yml`, 매일 00:17·06:17·12:17·18:17 UTC): 최근 2일치를 수집해 `archive.json` 에 추가하고 작업 브랜치에 커밋합니다. 42일 지난 기사는 지웁니다.
2. **매주 월요일 06:47 KST** (`news-publish.yml`): 한 번 더 수집 → 직전 7일로 점수 계산 → `data.js`·`latest.json` 을 작업 브랜치와 `main` 에 커밋 → GitHub Pages 재배포.
3. **eyefeet**: 페이지가 열릴 때 `/api/data` 가 `main` 의 `latest.json` 을 받아(10분 캐시) 더 새로우면 화면을 바꿉니다. 그래서 매주 다시 배포할 필요가 없습니다. 코드를 바꿨을 때만 정지 → 배포 → 시작 하면 됩니다.
4. **처음 시작할 때**: Actions → News collect → Run workflow 에서 `backfill` 을 켜면 직전 5주치를 주 단위로 받아 추세 비교 기준을 바로 만듭니다.
5. 이번 주 기사가 10건 미만이면 발행하지 않고 실패로 표시해, 수집이 멈춘 걸 알 수 있게 했습니다.

## 7. 한계

- 분류는 단어 규칙 기반이라 문맥을 놓칠 수 있습니다(예: 스포츠 "제재"). `AI_API_KEY` 를 GitHub Secrets 에 넣으면 AI 분류로 보완됩니다.
- Google 뉴스 검색은 질의당 결과 수에 상한(약 100건)이 있어, 아주 큰 이슈는 보도량이 실제보다 덜 잡힐 수 있습니다. 로그 정규화 덕분에 순위에는 영향이 작습니다.
- 백필한 과거 주는 검색 결과 기준이라, 6시간 수집이 쌓인 뒤(4주 이후)부터 추세(M)가 더 정확해집니다.
- 노출도와 조치 방향은 주가 방향이 아닙니다. 종목은 "영향권에 있는 대표 기업" 안내용입니다.
